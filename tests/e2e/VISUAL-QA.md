# Визуальный QA-прогон (Playwright)

Автотесты визуального QA рядом с существующими e2e. Три персоны:
- `visual-guest.e2e.spec.ts` — гость (без логина): главная, категория, публикация,
  поиск, подписка, 404 — в СВЕТЛОЙ и ТЁМНОЙ теме + мобильная главная.
- `visual-user.e2e.spec.ts` — подписчик (collection `subscribers`): /account,
  разблокированные реакции.
- `visual-studio.e2e.spec.ts` — автор (collection `users`, tenant+tenantRole):
  дашборд, экраны posts/videos/categories, композер, CRUD создания категории.

Каждый тест = функц. ассерты (жива/тенант резолвится/шапка/крошки/гейты) +
`toHaveScreenshot` (скриншот-регрессия). Динамика (картинки, даты, счётчики,
карусель героя) маскируется — см. `tests/helpers/visual.ts`.

## Запуск

Нужны: `npm run dev` (поднимется сам через webServer) + Postgres + активный тенант
(создаёт `global-setup.ts`). Персоны подписчик/автор сеются в beforeAll и чистятся
в afterAll (`tests/helpers/seedPersonas.ts`).

```bash
# 1) Первый раз — сгенерировать бейзлайн-скриншоты:
npm run test:e2e -- --update-snapshots

# 2) Обычный прогон (сравнение с бейзлайнами):
npm run test:e2e

# Только визуальные спеки:
npm run test:e2e -- visual-guest visual-user visual-studio

# Против прода (без локального dev; студийные/пользовательские сиды НЕ применятся —
# они лезут в локальную БД, поэтому для прода имеет смысл гость):
E2E_BASE_URL=https://btsrussia.ru npm run test:e2e -- visual-guest
```

Бейзлайны кладутся рядом со спеками (`*-snapshots/`). Коммить их вместе с тестами.

## Заметки / что может потребовать локальной правки
- Скриншот-бейзлайны детерминированы окружением (шрифты/рендер) — генерировать на
  той машине/образе, где будет CI.
- Гостевой спек берёт `/publication/rm` — если у тенанта иной слуг, поправить.
- Студийные селекторы (кнопки «Новая категория»/«Создать», плейсхолдеры) взяты из
  исходников на 2026-08-01; при редизайне студии — обновить.
- Автор проходит в студию только при `tenant.onboardingComplete=true` — это ставит
  `seedPersonas` на активном тенанте.
