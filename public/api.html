Внешний API Контент Бокс

Программно создавайте публикации: переносите контент с другой платформы с сохранением дат и уровней доступа или автоматизируйте рутину. Аутентификация — по ключу проекта в заголовке X-API-KEY.

Быстрый старт

За три шага

  • Откройте Студия → Настройки → API и нажмите «Сгенерировать ключ». Скопируйте его — значение показывается один раз.
  • Передавайте ключ в заголовке X-API-KEY. По ключу определяется ваш проект — домен указывать не нужно.
  • Отправьте POST на эндпоинт ниже. В ответ придёт ID и ссылки на пост.
Безопасность
Ключ храните в секрете (переменная окружения на вашей стороне). Мы не храним само значение — только его хеш; при утечке просто перегенерируйте ключ в настройках, старый сразу перестанет работать.
Аутентификация

Заголовки

X-API-KEY: cbx_ваш_ключ
Content-Type: application/json
accept: application/json

Один ключ на проект. Перегенерация немедленно отзывает прежний.

Публикации

Создать публикацию

POST https://contentbox.site/api/ext/v1/publications

Тело запроса

ПолеТипОписание
title обяз.stringЗаголовок, 4–256 символов.
textstringТело поста.
formatstringmarkdown (по умолчанию) или plain. HTML — позже.
publishedAtstringДата публикации в ISO 8601 (напр. 2026-06-17). Пусто — текущий момент.
categorySlugstringSlug раздела, куда попадёт публикация. Или categoryId.
extraCategorySlugsstring[]Дополнительные разделы.
accessstringall — бесплатно; tier — по подписке (см. minTierSlug).
minTierSlugstringУровень при access=tier. Пусто — низший платный уровень проекта.
coverUrlstringСсылка на обложку — скачаем и положим в наше хранилище.
tagsstring[]Теги публикации.
featuredbooleanЗакрепить/выделить.
isNewsbooleanПометить как новость.
seoTitlestringSEO-заголовок страницы.
seoDescriptionstringSEO-описание.
externalRefstringВаш ID поста на прежней платформе (напр. sponsr:51753). Дедуп: повторный импорт не создаст дубль.

Пример запроса

curl -X POST 'https://contentbox.site/api/ext/v1/publications' \
  -H 'X-API-KEY: cbx_ваш_ключ' \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Мой первый перенесённый пост",
    "text": "## Привет\n\nЭто **пост** с [ссылкой](https://example.com).",
    "format": "markdown",
    "publishedAt": "2026-06-17",
    "categorySlug": "weverse-live",
    "access": "tier",
    "coverUrl": "https://example.com/cover.jpg",
    "tags": ["bts", "live"],
    "externalRef": "sponsr:51753"
  }'

Ответ (200)

{
  "data": {
    "id": 123,
    "url": "https://ваш-домен/publication/moy-pervyy-perenesyonnyy-post",
    "editor": "https://ваш-домен/studio/posts/123"
  }
}

Ошибки

{ "message": "Неверный или отсутствующий X-API-KEY", "statusCode": 401 }
{ "message": "title должен быть 4..256 символов", "statusCode": 400 }
{ "message": "Категория не найдена: weverse-live", "statusCode": 400 }
Заметки

Как это работает

  • Доступ. all — публикация бесплатна и видна всем. tier без minTierSlug — доступ по любой активной подписке (низший платный уровень).
  • Даты. publishedAt сохраняется как есть — оригинальная хронология при переезде не теряется. Дата в будущем = отложенная публикация.
  • Повторный импорт. С externalRef повторный запуск вернёт уже созданную публикацию, а не создаст дубль — можно гонять миграцию несколько раз безопасно.
  • Обложки. coverUrl скачивается один раз в наше хранилище — на вашей стороне картинка может исчезнуть, у нас останется.
Скоро
Внешнее видео по ссылке (VK/Дзен), приём постов пачкой одним запросом, HTML-контент и приветственные письма подписчикам. Следите за разделом «Обновления».
